# tech_loop_prd — 设计前置关卡

方案批准前，**不得**调用实现技能或写代码。适用全项目。

## 工作流

| # | 步骤 | 约束 |
|---|------|------|
| 1 | **探上下文** — 扫代码/提交 | — |
| 2 | **分范围** — 多系统则拆子项目，定关系顺序 | 需拆项不细化 |
| 3 | **抓疑问** — 逐个问不确定项，首选项 | 一次一问 |
| 4 | **出2-3方案** — 含优劣，先推。例：`|A:独立模块|解耦周期长|B:嵌订单|改动小耦合高|` | 需给推荐理由 |
| 5 | **展示设计** — 按节：架构→组件→流→错→测。每节后问"可接收" | 🔴 **批后在继续** |
| 6 | **规格自检** — 扫：TODO/矛盾/范围/歧义/错误/待定 | — |
| 7 | **用户审核** — 审规格等回复 | 🔴 **批前不能继续** |
| 8 | **写详细设计** - 根据讨论的内容，咨询用户是否保存成文档，以及保存在哪里 | 详细方案设计 |


## 失败模式

| 问题 | 处理 |
|------|------|
| 方案全拒（Step4） | 问差距调向，必要时回 Step3 |
| 范围大拒拆（Step2） | 记风险，标注继续 |
| 被催"直接做" | gate：1-2句极简→确认→完成 |
| 问题无答案 | 按上下文假设，标待确认 |
| 审核出问题（Step7） | 回 Step6→自检→提交 |
| 设计节被否（Step5） | 只重做该节，通过节不变 |
| 无架构文档（Step1） | `ls`/`rg` 扫结构后继续 |
| 设计被连否3次 | 暂停，让用户理清需求再继续 |

## 规则
- 一次一问，首选项；视觉先单独邀
- **YAGNI**：只做明确需求
- **接口优先**：独立理解/测试/替换
- **循现有**：改前探结构，无关重构
- 多系统立即拆；每子项目独立 规格→计划→实现

## 反例

| # | ❌ 禁忌 | 理由 |
|---|--------|------|
| 1 | 一次问多问题 | 难一次答，易漏关键 |
| 2 | 替用户定不示选项 | 假设偏离，须展示确认 |
| 3 | 以"简单"跳过 gate | 简单项目是未检假设处 |
| 4 | 对需拆项目细化 | 浪费 token 细化将拆系统 |
| 5 | 方案未过写规格 | 方向错则白写 |
| 6 | 夹带未授权功能 | 违 YAGNI，增负担 |
| 7 | 不探上下文就出方案 | 未理解项目背景，方案必偏 |
| 8 | 只给一个方案不对比 | 缺少参照，用户无法判断最优 |
