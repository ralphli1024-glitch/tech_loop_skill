# 代码重构

## 质量检查（新代码完成后）
- **代码重复** → 抽取独立方法/类
- **方法过长** → 拆分为私有辅助方法，仅测试公共接口
- **模块职责单薄** → 合并或扩充
- **特征依恋** → 将逻辑迁移至数据所属类
- **基础类型滥用** → 引入值对象
- **已有代码暴露问题** → 一并修复

## 重构流程（历史代码）
1. 用户阐述问题 + 初步思路
2. 检索仓库核实代码状态
3. 给出备选方案，敲定落地细节
4. 明确重构边界（改什么、不改什么）
5. 核查测试覆盖率，不足则补
6. 拆分为最小粒度提交节点，每步确保运行正常

## 约束
- 所有测试通过后方可重构
- 每一步重构后运行测试
- 接口设计遵守 [design-an-interface.md](design-an-interface.md)
